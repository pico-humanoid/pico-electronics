# 装配、上电与联调

更新：2026-10-31。这是后续工作与验收安排，不是已完成测试记录。当前只确认 PCB 已下单等待到货；实物到位后与有经验的队友共同测量、接线和操作。

## 分阶段推进

| 阶段 | 电气工作 | 固件/其他组配合 | 完成标准与记录 |
| --- | --- | --- | --- |
| 0 等待到货 | 确认物流、贴片范围和缺件；核对订单、BOM、器件方向、接头及 H6 修改 | 固件核对现有引脚，机械核对金属紧固件外廓 | 版本与缺件清单、测试分工和时间；不只记录“板已完成” |
| 1 断电检查 | 外观、极性、桥连、接口线序、安装间距；核对 5V/3V3/GND、三路 H/L 与收发器的连接 | 准备准确原理图和引脚表 | 按明确测点保存检查结果，异常先定位；不带电测电阻/通断 |
| 2 仅控制侧上电 | 核对 Nucleo 跳线后，用合适限流电源先给 5V 控制侧供电，动力不接；分步确认 5V、3.3V、供电电流和异常发热 | 固件确认可烧录、日志、外接 LED 与蜂鸣器；具体供电/USB接法按板卡手册 | 测点、电压、电流、供电配置、运行时长、温度观察及固件版本；容许值取自器件手册与负载预算 |
| 3 三路 CAN 台架 | 按单路接 USB-CAN，逐路核对速率、H/L、参考地与终端 | 固件分别配置和验证 FDCAN1/2/3，保存两端日志与计数 | 三路分别有请求、发送完成、接收及错误统计；原 SN65HVD230 实验不能代替底板验收 |
| 4 单设备只读 | 先核对目标设备供电和线束，再接一台关节/BMS/电源板 | 固件读取身份、状态等安全查询，按各型号协议解析 | 原始请求/回复、ID、帧格式、DLC、速率、字段/单位和连续采集结果；暂不直接做整机运动 |
| 5 急停与受限单关节 | 先验证急停作用支路和恢复流程，再在固定支撑、确认范围下配合试动 | 固件/控制确定模式、限速限矩、方向、零位与停止动作，机械提供支撑 | 低风险条件下完成指令→反馈→停止；记录断连/失能结果和机械状态，不能只记“电机转了” |
| 6 多节点及整机 | 扩展线束，复核终端、压降、干扰和温升 | 固件/控制验证 ID、负载、时延、目标有效期、失联及上下位机接口 | 节点清单、报文率、错误/丢帧统计、供电与热记录、故障及恢复记录 |

板子未到不妨碍准备协议解析、离线数据、接口表和线束核对。到货后的焊接、上电、真实设备查询按实际条件排期，不预先写成“下周必然全部完成”。

## 测量和接线中的关键点

- 电压档并接测量；电流测量需采用合适串联或电流探头方案，不能把电流档直接跨接电源。
- 断电测 H/L 间电阻时，考虑设备内部电路和电容影响。两只 120Ω 并联通常接近 60Ω，可辅助排查终端，但该读数不能单独证明总线接对或通信正常。
- 每次只扩展一个因素：从控制侧到一条 CAN、一个设备，再到多节点；保留出问题前的接线与固件配置。
- 急停导致力矩消失时机构可能下落，测试支撑与故障动作需要机械、控制、电气和固件共同安排。

## 每次测试至少保存

```text
日期 / 参与人：
目的与阶段：
PCB订单/实板版本；原理图/工程版本：
开发板型号/修订；收发器与设备型号/版本：
固件commit/构建；工具版本：
接线照片；供电来源/跳线；测点与极性：
总线通道/速率/帧格式/ID；终端与参考地：
预定判据及依据：
实测电压/电流/温升/时长；收发计数与错误：
原始日志/波形/照片路径：
结论：通过 / 未通过 / 条件不足
遗留问题、下一动作与负责人：
```

不要将有灯亮、一次收发成功、DRC 通过或无负载上电，直接写为电机/整机联调完成。已有固件实验步骤与结果直接引用[CAN 验证操作](https://github.com/pico-humanoid/pico-firmware/blob/main/docs/can-bringup.md)、[10/27 实测报告](https://github.com/pico-humanoid/pico-firmware/blob/main/docs/validation/2026-10-27.md)，新底板单独补记录。
